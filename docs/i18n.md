# Translations

## Rules

- All source strings are English. English text is the translation key: `t('Cell voltage')`.
- Domain code (core, drivers, transport) never translates. It marks user facing strings with
  `msg('...')` (an identity function); the UI calls `t()` when rendering them.
- Placeholders use braces: `t('{count} change(s)', { count })`. Translations must keep every
  placeholder.
- Plurals: when a key needs real plural forms, its value in a catalog is an object keyed by
  `Intl.PluralRules` categories, for example in `uk.json`:
  `"{count} cells": { "one": "{count} комірка", "few": "{count} комірки", "many": "{count} комірок", "other": "{count} комірки" }`.
  `en.json` contains only such plural objects for English.
- Context: if the same English word needs different translations, prefix the key with a context
  and a bar: `t('noun|Charge')`. English output drops the prefix.
- Missing or empty translations fall back to English automatically.
- SI unit symbols (V, A, W, Ah, mV, °C) are not translated. Numbers use the locale's decimal
  separator through `Intl.NumberFormat`.
- No em dash in any text, including translations.

## Files

| Domain | Sources | Catalogs |
| --- | --- | --- |
| UI kit | `packages/ui/src` | `packages/ui/locales/<lang>.json` |
| App, core, drivers, transport | `apps/web/src`, `packages/*/src` | `apps/web/src/locales/<lang>.json` |

Languages: `uk`, `ru`, `de`, `fr` (English is the source). Adding a language: create the JSON
files, add the code to `LANGUAGES` in `apps/web/src/controller.js`, register the catalogs in
`apps/web/src/locales/index.js` and add it to `LANGS` in `scripts/i18n-check.mjs`.

## Tooling

```
npm run i18n:check                 # coverage, unused keys, placeholder and plural errors
node scripts/i18n-check.mjs --verbose
npm run i18n:extract               # writes <locales>/_template.json with every key
```

The checker extracts every literal passed to `t()` or `msg()`. Keep calls literal: dynamic
strings cannot be extracted (`t(variable)` is fine only when the variable holds a string that was
marked with `msg()` somewhere else).
